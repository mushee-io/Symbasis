## One-line summary

Symbasis is a Horizen testnet perpetual-exchange protocol combining onchain isolated-margin execution, AI-assisted risk controls, privacy-oriented strategy commitments and an autonomous simulated market-making layer for testnet liquidity and price movement.

## Problem

Perpetual trading systems expose strategy intent, require deep liquidity, and often separate execution UX from verifiable onchain settlement. Early-stage protocols also struggle to demonstrate a complete trading loop on testnet without pretending synthetic activity is real liquidity.

## Solution

Symbasis provides:

- deployed ETH-PERP and BTC-PERP market infrastructure on Horizen testnet;
- isolated-margin long/short execution, PnL settlement and liquidations;
- a vault for collateral and reserved margin;
- an explainable AI risk-assistance layer that recommends parameters but never signs for the user;
- private-mandate commitments where the browser keeps the raw text and only a hash is submitted onchain;
- a Symbasis MM testnet simulator that drives institutional-style candles, depth and fill tape while being clearly labelled simulated;
- a Stork-ready oracle path alongside the currently deployed controlled demo oracle.

## Why Horizen

Symbasis is built around an EVM-compatible perpetual execution stack on Horizen testnet while preparing for Horizen's confidential-compute direction. The current protocol uses public EVM contracts for settlement and commitments, and keeps VELA integration explicitly separated until a shared Horizen VELA testnet environment is available.

## AI / risk boundary

The current AI-risk baseline is advisory and explainable. It scores leverage, margin concentration, volatility and funding inputs and returns recommended leverage/margin parameters. It cannot access a private key, sign transactions or autonomously move user funds.

## Privacy boundary

What is private-oriented today:

- raw strategy mandate text stays in the browser;
- only a keccak256 commitment is submitted to the ConfidentialIntentRegistry;
- the protocol architecture is ready to move confidential execution into VELA when shared deployment support is available.

What is **not** private today:

- public Horizen testnet position state;
- public collateral/account state in the deployed EVM contracts;
- simulated MM activity is not confidential external market flow.

We do not claim otherwise.

## Market-data disclosure

Candles, bid/ask depth and fill tape are **simulated testnet market flow** generated by Symbasis MM and anchored to the configured oracle mark. They are not real liquidity, real volume or real counterparties. This is intentionally visible in the UI.

## Security / hardening completed

- strict Horizen chain-ID checks;
- isolated margin reservation;
- stale/non-positive oracle protection;
- demo-oracle per-update movement limits;
- market/OI/leverage caps;
- slippage bounds;
- pause controls while preserving close/liquidation paths;
- withdrawal restriction against reserved margin;
- reentrancy protection in the vault;
- two-step ownership utilities where implemented;
- automated contract tests;
- production web dependency audit;
- TypeScript and Next.js production build checks;
- live Horizen RPC/Stork bytecode CI check.

## Known limitations

Symbasis is testnet software and has not received a professional smart-contract audit. Current advanced LIMIT/TRIGGER controls are client-side testnet intents and require an explicit wallet execution; they are not keeper-executed native limit orders. The funding model is MVP-grade rather than a cumulative funding-index implementation. Shared VELA testnet deployment is not currently available.
